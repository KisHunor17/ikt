Mi az a DHCP?

A DHCP (Dynamic Host Configuration Protocol) egy hálózati protokoll, amely automatikusan oszt ki IP címeket és egyéb hálózati beállításokat a csatlakozó eszközöknek.

1. Manuális Címzés

Minden gépen kézzel kell beállítani az IP címet, maszkot és átjárót. Lassú, hibaveszélyes (IP ütközések) és nagy hálózatoknál fenntarthatatlan.

2. BOOTP Protokoll

A DHCP elődje (Bootstrap Protocol). Képes volt hálózati indításra, de fix MAC-IP táblázatokat igényelt a szerveren, és nem ismerte a dinamikus bérleti időt.

3. DHCP (Automatikus)

Teljesen automatizált és dinamikus! Címkészletből (pool) oszt ki címet ideiglenes bérlettel (Lease), majd használat után automatikusan visszaveszi azt.

A DORA Lépések Részletei

A DORA betűszó a folyamat négy fázisának kezdőbetűiből áll össze: Discover, Offer, Request, Acknowledge.

D Client → Broadcast

1. DHCP Discover (Felfedezés)

Az újonnan csatlakozó Kliensnek még nincs IP címe, és azt sem tudja, van-e DHCP szerver a hálózaton. Ezért egy L2 és L3 Broadcast üzenetet küld ki.

  • Forrás IP: 0.0.0.0
  • Cél IP: 255.255.255.255 (Broadcast)
  • UDP Portok: 68 (Src) → 67 (Dst)
O Server → Client

2. DHCP Offer (Ajánlat)

A DHCP szerver veszi a Discover üzenetet, választ egy szabad IP címet a címkészletből (Pool), és felajánlja azt a kliens MAC címének intézve.

  • Felajánlott IP (yiaddr): 192.168.1.100
  • Bérleti Idő: 86400 mp (24 óra)
  • UDP Portok: 67 (Src) → 68 (Dst)
R Client → Broadcast

3. DHCP Request (Kérés)

A Kliens elfogadja az ajánlatot. Az üzenetet Broadcast-ként küldi el, hogy a hálózat esetleges többi DHCP szervere is értesüljön arról, hogy az ő ajánlatukat nem vette igénybe.

  • Kért IP (Option 50): 192.168.1.100
  • Kiválasztott Szerver (Option 54): 192.168.1.1
  • Cél IP: 255.255.255.255
A Server → Client

4. DHCP ACK (Megerősítés)

A szerver véglegesíti a bérletet az adatbázisában, és elküldi a végleges konfig paramétereket (Subnet Mask, Default Gateway, DNS szerverek).

  • Konfiguráció: Mask, Gateway, DNS
  • Kliens Állapot: IP Beállítva & Aktív
  • Siker: Hálózati kapcsolat kész!

Bérleti Idő (Lease Time) & Megújítási Idővonal

A kapott IP cím nem örökre szól. Kövesd nyomon, mi történik a bérleti idő előrehaladtával!

0% (Kezdet) T1 Timer (50%) T2 Timer (87.5%) 100% (Lejárat)
0% - IP Megszerzése

Bérlet Elindul

A kliens megkapta az IP címet. A T1 és T2 időzítők elindulnak.

T1 Timer (50%)

Unicast Megújítás

A kliens egy Unicast DHCPREQUEST-et küld a meglévő szervernek.

T2 Timer (87.5%)

Broadcast Rebind

Ha az eredeti szerver nem válaszolt, a kliens Broadcast-ként kér újrasorolást bármely szervertől.

100% Lejárat

Cím Elvesztése

A bérleti idő lejárt. Az IP cím érvénytelen. A kliens törli a címet és új DORA-t indít.

Helyzet: A kliens friss bérlettel rendelkezik. Nincs szükség hálózati forgalomra.

DHCP Release (Önkéntes Elengedés)

Amikor a gép leáll vagy lekapcsolódik a hálózatról, egy DHCPRELEASE üzenetet küldhet a szervernek, így az IP azonnal újra kioszthatóvá válik.

DHCP Biztonsági Fenyegetések

1. Rogue DHCP Server (Gonosz Szerver) Egy jogosulatlan DHCP szerver hamis hálózati adatokat (pl. saját magát mint Default Gateway) oszt ki Man-in-the-Middle támadáshoz.
2. DHCP Starvation (Címkimerítés) A támadó hamis MAC címek ezreivel kimeríti a DHCP pool összes elosztható IP címét.
Védekezés: DHCP Snooping A switcheken beállított funkció, amely csak a megbízható (Trusted) portokról engedélyezi a DHCP Offer és ACK csomagokat.
